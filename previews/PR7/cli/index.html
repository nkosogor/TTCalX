CLI Reference

Both scripts take one sources file and any number of MSes; pass all MSes in one call so that only the first pays the Julia compilation. They read and write the same column (--column, default CORRECTED_DATA) in place. Exit code 0 on success, 1 on invalid arguments or missing python-casacore. Environment: Installation. The imager CLI (ttcalx-image) is described in GPU CLEAN imager.

bin/zest_sky_rfi.jl

julia bin/zest_sky_rfi.jl [options] <sources.json> <ms1> [ms2] ...

Peels the sky sources, then the near-field RFI emitters (zest_sky_rfi_ms!): RK4 StefCal as CPU TTCal, exact sky model, geometric UVW, residual-power guard. The defaults are the production settings.

optiondefaultdescription
--rfi=FILEnonenear-field RFI model (JSON entries with rfi-frequencies)
--rfi-mode=MODEafterafter (separate pass after the sky) or joint (extra directions)
--solver=Srk4rk4 or damped
--maxiter=N5max StefCal iterations per solve
--tolerance=T1e-4convergence tolerance
--minuvw=M5.0min baseline length (wavelengths)
--peeliter=P3peeling passes
--max-gain=G100reject solutions with |g| > G
--min-elevation=E0skip sky sources below E degrees
--reg=O,T[,L]offTukey phase prior: max offset O deg, taper T deg, weight L; not with --smooth-flux
--smooth-flux=S0 (off)directions fainter than ~S Jy get one band gain instead of per-channel gains (suggested 1000)
--rfi-smooth-flux=S--smooth-fluxthe same for the RFI emitters
--smooth-exempt-flux=Fnonesky sources with catalog flux ≥ F Jy keep per-channel gains (suggested 1e4)
--restore=FILEnonepoint sources (e.g. Jupiter at its ephemeris position) given back after peeling; the name must not be exactly Sun, Moon or Jupiter
--restore-below-mhz=Falwaysrestore only when the band starts below F MHz
--restore-offset=D0search radius (deg) for the restored position on Stokes V (0.5 for Jupiter)
--precision=Pdoublemixed: single-precision normal equations (~3-4x faster on GPUs with slow FP64; tolerance floored at 1e-6)
--warm-startoffstart from the previous MS's gains (same channels, ≤ 60 s apart)
--peeloffdiagonal Jones instead of full Jones
--keep-zerosoffdo not flag exactly-zero visibilities
--cpuoffCPU threads instead of the GPU (julia -t N)
--column=COLCORRECTED_DATAMS column to read and write
--verbose / --quiet / --helpevery source update / errors only / help
julia bin/zest_sky_rfi.jl --rfi=sources/rfi_43.2_ver20251101.json sources/sources_7src_tauA.json *.ms
julia -t 24 bin/zest_sky_rfi.jl --cpu --reg=0.5,0.5 sources.json data.ms
julia bin/zest_sky_rfi.jl --rfi=rfi.json --smooth-flux=1000 --smooth-exempt-flux=1e4 \
      --restore=jupiter.json --restore-below-mhz=41 --restore-offset=0.5 sources.json *.ms

bin/ttcal_gpu.jl

julia bin/ttcal_gpu.jl <command> [options] <sources.json> <ms1> [ms2] ...

Damped StefCal with the kernel sky model and the MS UVW (peel_gpu! and friends).

commandJonesfrequency
peeldiagonalper channel
zestfullper channel
shavediagonalwideband (one per subband)
prunefullwideband (one per subband)
optiondefaultdescription
--maxiter=N30max StefCal iterations per solve
--tolerance=T1e-4convergence tolerance
--minuvw=M10.0min baseline length (wavelengths)
--peeliter=P3peeling passes
--column=COLCORRECTED_DATAMS column to read and write
--verbose / --quiet / --helpper-source output / errors only / help
julia bin/ttcal_gpu.jl zest sources/sources_7src_tauA.json *.ms
julia bin/ttcal_gpu.jl peel --maxiter=50 --minuvw=15 --column=DATA sources.json data.ms

The script's defaults differ from the library's (peel_gpu! defaults: maxiter=20, tolerance=1e-3, minuvw=0).
