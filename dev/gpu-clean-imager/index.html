GPU CLEAN imager (ttcalx_imager)

python/ttcalx_imager is a Python package (CuPy + cuFINUFFT + python-casacore) that makes the OVRO-LWA imaging products of the main (orca) pipeline on one GPU, from peeled snapshot measurement sets:

ProductCommandWSClean equivalent (orca)
10-s snapshot, Stokes I CLEANttcalx-image snapshotSNAPSHOT_CLEAN_I_PARAMS
10-s snapshot, Stokes V dirty + QAttcalx-image snapshotSNAPSHOT_PARAMS (pilot V) + analyze_snapshot_quality
1-h Stokes I, multiscale CLEANttcalx-image hourI-Deep-Taper-Robust-0
6 x 10-min Stokes Ittcalx-image hourI-Taper-10min
1-h / 10-min Stokes V dirtyttcalx-image hourV-Taper-Deep, V-Taper-10min

The hour command replaces concat, chgcentre, pilot snapshots and the WSClean runs; it does not run AOFlagger on the concatenated hour (see Limitations).

Installation and usage

python -m venv venv && . venv/bin/activate
pip install numpy==1.26.4 scipy astropy python-casacore cupy-cuda12x==13.6.0 cufinufft==2.5.1
pip install -e python/ttcalx_imager[test]
export NUMPY_MADVISE_HUGEPAGE=0     # calim nodes: numpy THP madvise causes multi-second stalls
export CUPY_CACHE_DIR=/somewhere/with/space   # not $HOME if the home quota is full

# 10-s snapshots (one persistent process: plans and w-term tables are cached per geometry)
ttcalx-image snapshot /data/41MHz/*.ms --out-dir snap41/ [--keep-aux] [--write-psf]
#   -> snap41/<stem>-I-image.fits, <stem>-V-image.fits, <stem>-qa.json

# one band-hour: 1 h + 6 x 10 min, I and V, orca phase centre for LST hour 2
ttcalx-image hour @list41.txt --band 41 --out hour41/41MHz --lst-hour 2 --qa-dir snap41/
#   -> hour41/41MHz-1h-{I-image,I-residual,I-model,I-dirty,psf,V-image}.fits
#      hour41/41MHz-10min-t000N-...fits, hour41/41MHz-summary.json

The same band-hour from a GSIV archive (gsi v3: one record file per band-hour instead of ~358 MSes, written by gpu-subband-imaging v3/hourstore.py; ttcalx_imager.gsiv). The records hold I and V per kept sample and uvw / natural weight / kept mask per row, and load_archive rebuilds u, v, w, nw with the msio.load_samples expressions, so u, v, w, nw, I and V are those of the MS run bit for bit. R is the writer's load_samples R: casacore's measures caching makes it depend on the call order in a process (~1e-10), as between two process-pool loads of the MSes. Loading is strict: a torn, partial, corrupt or mixed-band archive raises GSIVError, and the newest record of a stem wins. QA rejections can be given by stem:

ttcalx-image hour --archive a.gsiv[,b.gsiv] --band 41 --out hour41/41MHz --lst-hour 2 \
    --products orca --qa none --exclude-stems @rejected-stems.txt

All main-pipeline hourly products from one load of the data, with WSClean's file names (<prefix>-I-Deep-Taper-Robust-0-image.fits, -residual, -model, -dirty, -psf, <prefix>-I-Taper-10min-t0000-image.fits, <prefix>-V-Taper-Deep-image.fits, ...):

ttcalx-image hour @list41.txt --band 41 --out hour41/41MHz --qa compute \
    --products I-Deep-Taper-Robust-0,I-Deep-Taper-Robust-0.75,I-Deep-NoTaper-Robust-0.75,I-Deep-NoTaper-Robust-0,I-Taper-10min,V-Taper-Deep,V-Taper-10min
#   (--products orca = the same list)

All use multiscale (bias 0.8), mgain 0.95, auto-mask 3, auto-threshold 0.5, local RMS and the 10 deg horizon mask (orca IMAGING_STEPS). A V product requested without its I product is made without CLEAN. Snapshot QA always uses the pilot weighting (briggs 0, Tukey 30). The summary JSON times every step per product ("<product>: <step>").

The geometry follows the orca tiers (bands.py): 18-36 MHz 1507 px at 0.0767 deg, 41-59 MHz 2357 px at 0.049 deg, 64-82 MHz 3122 px at 0.037 deg; as in WSClean, odd sizes are rounded up to even (2357 -> 2358).

Python API: ttcalx_imager.snapshot.SnapshotImager().image(ms, out_prefix=...), ttcalx_imager.hour.image_hour(paths, band, out_prefix, ...).

What it does

Snapshot. Read the MS (casacore), form I = (XX+YY)/2 and V = i(YX-XY)/2 with the XX|YY flag mask, compute Briggs weights on the GPU, grid dirty I and the PSF with cuFINUFFT (w-term by SVD factorisation, see below), run Clark/Hogbom CLEAN with WSClean's auto-mask, auto-threshold and local-RMS logic and two exact major cycles (DFT prediction of the sparse model, degridding above 8000 components), restore with the WSClean beam fit, and grid dirty V with the same weights. QA (<stem>-qa.json): std of the central 1024 x 1024 pixels of V (the orca statistic), V peak, residual rms/MAD, flag and exactly-zero fractions, beam, iteration counts, timings. Snapshots with no unflagged or only zero data get status: "empty" and no images.

Hour. Load all snapshots in worker processes and compute each one's exact rotation to the hour phase centre; reject snapshots by the orca QA rule (V rms > median + 3 MAD-std or < 0.5 median; V rms from the snapshot QA JSON when available, otherwise computed); build one Briggs density grid over all accepted samples (the weighting WSClean applies to the concatenated MS); grid by w-snapshots: blocks of 6 consecutive snapshots are gridded in the frame of their middle snapshot, where |w| is small, and reprojected to the hour SIN grid; multiscale CLEAN with WSClean-style major cycles in which the model is reprojected to each block frame and degridded there; restore with the WSClean beam fit of the hour PSF. The 10-min images use -intervals-out 6 boundaries on the original time-step index.

Conventions

  • Gridding kernel: I(l, m) = Re sum c exp(+2 pi i (u l + v m - w (n - 1))), prediction is the adjoint (WSClean/ducc0 convention, divide_by_n=False). Consequently (l, m, -n) transforms like (u, v, w) under a phase-centre rotation, which is what the w-snapshot reprojection uses.
  • Orientation: raw NUFFT arrays are [ix(l), iy(m)]; images are stored in WSClean/FITS memory order [y, x] with x = ix and y = (N - iy) mod N (RA increases to the left, CDELT1 < 0). The image centre is pixel (N/2, N/2) (0-based), CRPIX = N/2 + 1.
  • w-term: exp(-2 pi i w (n - 1)) = exp(i pi w) exp(-2 pi i w x'), x' = n - 1/2, and the second factor is approximated by sumk ak(w) b_k(x') from an SVD on a (w, x') grid with max error 1e-4. Each term is one 2-D NUFFT; K ~ 6-8 for a snapshot or a w-snapshot block, ~25-37 if the whole hour were gridded in the hour frame (--mode vis).
  • Phase rotation: uvwnew = R uvwstored with R fitted to casacore-measures UVW (A[a1] - A[a2], the MS sign convention; includes precession/nutation/aberration as chgcentre), visnew = vis exp(+2 pi i (wstored - w_new) / lambda).
  • Reprojection flux: dirty/residual images (Jy/beam) are resampled as-is; a model (Jy/pixel) moved from frame A to frame B is multiplied by the SIN pixel solid-angle Jacobian nA / nB.
  • Stokes V = i (YX - XY) / 2 for XX, XY, YX, YY correlations (verified against wsclean -pol IV).
  • Restoring beam: BPA from north (+y) through east (-x), as in the FITS header.

Restoring-beam fit

beam.py ports WSClean 3.4's PSF fit: box = 10 x theoretical beam (1 / max|uvw|) rounded up to even and grown until it exceeds 8 x the fitted FWHM; Levenberg-Marquardt fit of a peak-1 centred elliptical Gaussian (sigmax, sigmay, beta) including negative pixels; eigen decomposition with aocommon's eigenvector convention for the PA. The C++ evaluates pixel offsets as unsigned integers, so pixels left of or below the centre get a model value of exactly 0 and only one quadrant of the box constrains the fit; the port reproduces this deliberately. On WSClean's own PSFs the port returns WSClean's BMAJ/BMIN to ~1e-6 and BPA to ~1e-5 deg (a full-box fit would be 1-2 % off). The prototype's main-lobe fit was 1-3 % wider than WSClean's.

These are float32 rounding differences amplified by CLEAN decisions: two runs of the prototype itself differ by the same amount (e.g. 1.3e-4 sigma rms for a 69 MHz snapshot, 9e-5 sigma for the 69 MHz hour) because cuFINUFFT spreads with atomic additions.

Limitations

  • Stokes I (CLEAN) and V (dirty) only; no Q/U, no MFS / multi-frequency deconvolution (one spectral window imaged as a single channel) and no spectral cubes.
  • No primary-beam correction and no dewarping; outputs correspond to WSClean -image files.
  • Only the orca deep configuration (Briggs 0, inner Tukey 30 lambda, multiscale bias 0.8, auto-mask 3 / auto-threshold 0.5, 1 h and 10 min) and the snapshot configuration are validated against WSClean. The robust -0.75 and no-taper presets use the same code paths (the Briggs weights for robust -0.75 and no taper are unit-tested) but are not yet compared with WSClean images.
  • The hour mode does not run AOFlagger on the concatenated hour; inputs are the peeled snapshots as they are (in the 2026-10-23 prototype test, skipping AOFlagger changed the 1-h difference to the main pipeline from 0.111 to 0.114 sigma).
  • The snapshot clean always does 2 major cycles (no -mgain convergence test).
  • The hour mode needs the peeled snapshot MSes; the GPU subband-imaging worker currently deletes each peeled MS after imaging it.
  • cuFINUFFT uses atomic additions, so results are reproducible only to float32 rounding (~1e-7 of the noise for dirty images; CLEAN can amplify this to ~1e-4-1e-3 sigma rms).
  • python-casacore's bundled measures tables may be older than the data (it logs "IERS table" warnings); UT1-UTC is then taken as 0, an error of < 1 s in time (< 15 arcsec, < 0.1 pixel).
